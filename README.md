# 🧪 JIRA Test Case Generator

> A locally-hosted web application that connects to your JIRA instance, fetches ticket details, and generates structured QA test cases using the **RICPOT methodology** with strict **anti-hallucination rules**.

![Node.js](https://img.shields.io/badge/Node.js-18%2B-green?logo=node.js) ![License](https://img.shields.io/badge/License-MIT-blue) ![No Dependencies](https://img.shields.io/badge/Dependencies-Zero%20Required-brightgreen)

---

## ✨ Features

- 🔗 **Live JIRA Integration** — connects to any Atlassian JIRA instance via API token
- 🛡️ **Anti-Hallucination Engine** — never generates test cases by assumption; all TCs are strictly derived from ticket content
- ⚠️ **Empty Ticket Detection** — responds clearly when a JIRA ticket has no details instead of inventing content
- 📋 **RICPOT Methodology** — structured test case generation (Role, Instruction, Context, Parameters, Output, Tonality)
- 📊 **Rich Table Output** — TC ID, Title, Scenario Type, Preconditions, Test Steps, Expected Result, Priority, Confidence
- 📥 **Export Options** — Copy as Markdown or Download as CSV
- 🎭 **Demo / Offline Mode** — works out-of-the-box with 3 built-in mock JIRA tickets (no credentials needed)
- 🔒 **Zero secrets in code** — all credentials stored only in `.env` and browser localStorage

## 🚀 Quick Start

### 1. Clone the Repository

```bash
git clone https://github.com/your-username/jira-testcase-generator.git
cd jira-testcase-generator
```

### 2. Install Dependencies

```bash
npm install
```

### 3. Configure Environment

Copy the example environment file and fill in your details:

```bash
cp .env.example .env
```

Open `.env` in any text editor:

```env
# Server Port
PORT=8080

# JIRA Configuration
JIRA_URL=https://your-domain.atlassian.net
JIRA_EMAIL=your-email@company.com
JIRA_API_TOKEN=your_jira_api_token_here

# Optional: Google Gemini API Key (for future LLM features)
GEMINI_API_KEY=your_gemini_api_key_here
```

> ⚠️ **Never commit your `.env` file.** It is already added to `.gitignore`.

### 4. Start the Server

```bash
npm start
```

The app will be running at **[http://127.0.0.1:8080](http://127.0.0.1:8080)**

## 🔑 How to Get a JIRA API Token

1. Go to [https://id.atlassian.com/manage-profile/security/api-tokens](https://id.atlassian.com/manage-profile/security/api-tokens)
2. Click **Create API Token**
3. Give it a label (e.g. `jira-testcase-generator`)
4. Copy the generated token
5. Paste it into your `.env` file as `JIRA_API_TOKEN`

## 🧭 Using the App

### Step 1 — Open the App
Navigate to [http://127.0.0.1:8080](http://127.0.0.1:8080) in your browser.

### Step 2 — Connect to JIRA (Optional)
Click the **⚙️ Settings** button (top-right):
- Enter your **JIRA Base URL** (e.g. `https://mycompany.atlassian.net`)
- Enter your **Email** and **API Token**
- Click **Connect** — the app will validate your credentials and show a success/failure message
- Click **Cancel** at any time to abort the connection check

### Step 3 — Generate Test Cases
In the prompt box, type a natural language request like:

```
please create test cases for JIRA-121
```

The app will:
1. Fetch the JIRA ticket details
2. Show a **ticket summary** (title, type, priority, key requirements)
3. Generate a **table of up to 15 test cases** (Critical & Major scenarios)
4. Alert if **more coverage is needed** beyond 15 cases
5. Display a **warning if the ticket is empty** — no TCs generated by assumption

### Step 4 — Export Results
- **📋 Copy Markdown** — copies the test cases as a formatted Markdown table
- **📥 Download CSV** — exports all test cases as a `.csv` file

## 🛡️ Anti-Hallucination Rules

The engine enforces strict compliance:

| Rule | Behaviour |
|------|-----------|
| **Empty Ticket** | Responds: *"JIRA ticket is empty. No test cases generated."* — never invents content |
| **No Feature Invention** | Never creates test cases for features not mentioned in the ticket |
| **No Default Assumptions** | Never assumes typical system behaviour unless explicitly specified |
| **Missing Info Flagged** | Lists all missing/ambiguous details explicitly under ⚠️ notices |
| **Inferred Steps Labelled** | Any inferred precondition is tagged `[Inference (low confidence)]` |
| **Max 15 Initial Cases** | Caps the initial generation at 15; offers to load more if needed |

## 🧪 Running Tests (Manual Verification)

You can verify the API endpoints directly with `curl`:

```bash
# Test connection to JIRA
curl -s -X POST http://127.0.0.1:8080/api/jira/connect \
  -H "Content-Type: application/json" \
  -d '{"jiraUrl":"https://your-domain.atlassian.net","jiraEmail":"you@example.com","jiraApiToken":"your_token"}'

# Fetch a demo ticket
curl -s -X POST http://127.0.0.1:8080/api/jira/issue \
  -H "Content-Type: application/json" \
  -d '{"issueKey":"JIRA-121"}'

# Generate test cases for a ticket
curl -s -X POST http://127.0.0.1:8080/api/generate-testcases \
  -H "Content-Type: application/json" \
  -d '{"ticket":{"key":"JIRA-121","summary":"OAuth 2.0 Login","description":"User can log in using Google OAuth 2.0."}}'

# Test empty ticket handling
curl -s -X POST http://127.0.0.1:8080/api/jira/issue \
  -H "Content-Type: application/json" \
  -d '{"issueKey":"JIRA-EMPTY"}'
```

## ❓ Troubleshooting

| Issue | Solution |
|-------|----------|
| `EADDRINUSE` port error | Another process is using port 8080. Change `PORT` in `.env` |
| JIRA connection fails (401) | Check your email and API token in Settings |
| JIRA connection fails (404) | Verify the JIRA Base URL (should not end with `/`) |
| Ticket not found | Use the demo tickets (`JIRA-121`, `QA-1042`, `PROJ-789`) or configure live credentials |
| Empty ticket message shown | The JIRA ticket has no description/summary — add details to the ticket first |
